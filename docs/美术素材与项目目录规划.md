# 《星火燎原》美术素材与项目目录规划

## 1. 基本原则

- 原始文件、编辑文件和 App 运行时文件分离。
- SpriteKit 使用的正式资源统一进入 Xcode Asset Catalog 或资源 Bundle。
- 文件名使用英文小写、下划线和版本号，避免中文、空格和特殊字符。
- 同一素材只保留一个正式运行时版本，避免项目中出现 `final2`、`new`、`真的最终` 等重复文件。
- 程序化绘制只负责战斗特效、弹幕、粒子、部分背景和简单图标；角色、Boss、主要 UI 和剧情头像使用正式 2D 资源。
- 所有素材必须支持离线运行，不能依赖 Google Fonts、远程图片或远程 CDN。

## 2. 推荐文件格式

### 2.1 SpriteKit 战斗素材

| 素材 | 制作源文件 | App 运行时格式 | 说明 |
| --- | --- | --- | --- |
| 飞船、敌人、Boss | PSD/KRA/AFDESIGN | PNG | 需要透明背景和多尺寸适配 |
| 爆炸、火花、弹道 | AE/Blender/绘图源 | PNG 序列或纹理图集 | 小尺寸、高频使用，优先图集 |
| 复杂背景 | PSD/KRA | PNG 或 HEIF/JPEG | 不需要透明时使用压缩格式 |
| Sprite 动画 | PSD/KRA/AE | `.atlas` 内 PNG | 统一帧尺寸和命名 |
| 角色头像 | PSD/KRA | PNG | 透明背景，建议 1x/2x/3x |
| 纹理/噪声 | 程序源或图像源 | PNG | 低分辨率可平铺，避免大图重复 |

推荐规则：

- 需要透明的素材使用 PNG-24/PNG-32。
- 不透明的大型背景使用 HEIF 或 JPEG；保留 PNG 源作为高质量备份。
- 不把 PSD、KRA、Figma 导出文件直接放入 App Target。
- 不把 SVG 直接作为 SpriteKit 运行时纹理；SVG 可作为设计源，导出 PNG 后使用。
- 不使用 GIF；动画使用 SpriteKit 图集、PNG 序列或程序化粒子。

### 2.2 SwiftUI 和 UI 素材

| 素材 | 推荐格式 |
| --- | --- |
| 图标 | SF Symbols 优先；自定义图标使用 PDF/SVG 源并进入 Asset Catalog |
| 纯色、渐变、主题色 | Xcode Color Set |
| 面板纹理、边框、扫描线 | PDF、PNG 或程序化绘制 |
| 角色/敌人头像 | PNG |
| App Icon | Xcode AppIcon Asset Catalog，提供完整尺寸 |
| 字体 | OTF 优先，TTF 作为兼容格式 |
| 中文/英文文本 | `.xcstrings`；富文本或剧情变量使用 JSON |

UI 中能用 SF Symbols 表达的按钮不重复绘制位图图标。必须支持深色背景、加大文字和色弱模式下的辨识。

### 2.3 音频格式

| 音频 | 制作/归档格式 | App 格式 |
| --- | --- | --- |
| 音效源文件 | WAV 48 kHz/24-bit | CAF 或压缩音效资源 |
| 短音效 | WAV | CAF，单声道或立体声按需要 |
| 背景音乐源文件 | WAV/AIFF | M4A/AAC 或 CAF |
| 通讯提示音 | WAV | CAF |
| 角色配音 | 首版不制作 | 不加入 Target |

音频文件名必须包含用途和变体，例如 `sfx_bob_lock_on_01.caf`、`music_ch03_rebel.m4a`。

## 3. 尺寸和密度规范

所有设计以逻辑点为基准，不以单一设备像素为基准。

### 3.1 战斗素材

- 玩家战机逻辑尺寸约 48 至 96 pt，实际纹理提供 2x 和 3x。
- 普通敌人逻辑尺寸约 24 至 64 pt。
- 精英敌人逻辑尺寸约 80 至 140 pt。
- Boss 纹理按屏幕占用面积拆分，不制作一张超过 4096 px 的超大纹理。
- 粒子、子弹和小图标尽量控制在 256 px 以内。

### 3.2 UI 素材

- 触控目标不小于 44 x 44 pt。
- 重要 HUD 文本不小于 14 pt，战斗关键数值建议 16 至 20 pt。
- 头像提供 128x128、256x256 和 384x384 的透明 PNG。
- 全屏背景按最宽目标设备的逻辑比例设计，重要内容避开安全区域。
- iPad 复用 iPhone 信息布局，不额外分裂为两套资源；允许背景在更大屏幕上扩展裁切。

## 4. 命名规范

### 4.1 通用格式

```text
[category]_[id]_[state]_[variant]_[scale].[ext]
```

示例：

```text
ship_alice_idle_red@2x.png
ship_alice_boost_red@3x.png
enemy_scout_empire_idle@2x.png
boss_bob_phase_02@3x.png
portrait_charlie_dialogue_angry@2x.png
fx_explosion_metal_03@2x.png
ui_hud_armor_segment_full@3x.png
sfx_bob_lock_on_01.caf
music_ch03_rebel.m4a
```

### 4.2 状态后缀

统一使用：

`idle`、`move`、`hit`、`damage`、`destroy`、`boost`、`phase_01`、`phase_02`、`success`、`failure`、`locked`、`selected`。

不要在文件名中写中文、颜色名称、临时版本或设计师姓名。颜色和阵营应由素材配置或代码主题控制。

## 6. 目录职责

### 6.1 `Starfire/Resources`

只放已经审核、可以进入 App 的运行时资源。所有文件都被 Xcode Target 管理，禁止把制作源文件放入这里。

### 6.2 `ArtSource`

存放 PSD、KRA、AFDESIGN、原始 SVG、Blender 和导出说明。源文件可以很大，但必须有预览图和版本说明。

每个美术资产目录建议包含：

```text
ship_alice/
├── source/
├── preview.png
├── export.json
└── README.md
```

### 6.3 `ArtSource/Exports`

存放从源文件导出的中间文件，不直接作为正式运行时资源。审核通过后复制到 `Starfire/Resources` 或进入 Asset Catalog。

### 6.4 `Data/Content`

存放可热更新式编辑但随 App 打包的静态配置：敌人、Boss、波次、掉落、升级、对话和本地化键。首版不联网，因此这些内容随版本发布。

### 6.5 `Tools`

自动执行：

- 检查文件名和尺寸。
- 检查 PNG 是否存在意外全透明区域。
- 检查 JSON ID 是否重复。
- 检查对话是否缺少中文或英文翻译。
- 检查 Boss、Rogue 物品和升级引用的 ID 是否存在。
- 生成纹理图集并输出资源清单。

## 7. Git 管理规则

- 代码、JSON、`.xcassets`、小型 PNG 和压缩音频进入 Git。
- PSD、KRA、原始音频和大型视频建议使用 Git LFS 或团队资产库。
- 不提交 Xcode DerivedData、构建产物、临时导出目录和个人本地配置。
- 每个正式资源必须能追溯到一个源文件和一个导出记录。
- 删除资源前先检查 JSON、Swift 和测试中的引用。

## 8. 资源验收清单

- 是否有透明背景、正确尺寸和正确色彩空间。
- 是否有 2x/3x 或 Asset Catalog 的密度配置。
- 是否在 iPhone 和 iPad 横屏显示完整。
- 是否不会遮挡弹幕、Boss 弱点和触控按钮。
- 是否命名符合规范并且 ID 唯一。
- 是否包含中文和英文需要的文本资源。
- 是否通过离线启动和内容校验。
- 是否在低性能设备上控制纹理尺寸和粒子数量。
