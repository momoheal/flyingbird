# 问题管理员手册

## 目的

任何 Bug 在修复前必须留下可复现记录；任何 Bug 在关闭前必须有根因、修复文件和回归验证。聊天里的“已修”不作为关闭依据。

## 生命周期

`OPEN -> TRIAGED -> IN_PROGRESS -> FIXED -> VERIFIED -> CLOSED`，也可以结束为 `WONT_FIX` 或 `DUPLICATE`。

## 必填字段

每个问题必须包含：`id`、`title`、`status`、`priority`、`first_seen`、`repro_steps`、`expected`、`actual`、`root_cause`、`fix_files`、`verification`、`verified_at`、`regression_test`。

优先级：P0 为无法启动/数据损坏，P1 为核心关卡或分支错误，P2 为局部功能或视觉错误，P3 为文案和低风险改进。

## 管理命令

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\issue_admin.ps1 -Action list
powershell -NoProfile -ExecutionPolicy Bypass -File tools\issue_admin.ps1 -Action new -Title "第二章 Boss 不出现" -Priority P1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\issue_admin.ps1 -Action verify -Id FB-0001 -Verification "tools\\run_checks.ps1; 手工走保护线" -RegressionTest "第一章 Boss 到第二章转场"
powershell -NoProfile -ExecutionPolicy Bypass -File tools\issue_admin.ps1 -Action close -Id FB-0001
```

数据保存在 `docs/issues.json`。`close` 在缺少验证或回归测试时拒绝关闭。

## 修复规则

1. 先复现，后改代码。
2. 根因必须描述为什么发生，不能只写“调整参数”。
3. 修复后运行相关自动检查，并走一次原始复现路径。
4. 同一现象再次出现时更新原 Issue，不新建重复条目。
5. 关闭前检查相邻流程：第一章问题要检查第一章到第二章衔接，Boss 问题要检查普通波次和失败重开。
