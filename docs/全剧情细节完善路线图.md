# 全剧情细节完善路线图

> 目标：先保证玩家能从序章连续走到第九章与三条终局，再以可验证的小批次补足人物、关卡、演出、美术和数值细节。剧情事实以 `星火燎原-多视角剧情小说.md` 为准；玩法映射以 `剧情设计文档.md` 为准。

## 0. 当前已完成的故事骨架

当前 HTML 原型已可沿下列链路推进：

```text
序章：赵利俄斯护航战
  -> 第一章：镇压与谎言
  -> 第二章：检疫井之前
  -> 第三章：旧友的倒戈
  -> 第四章：锈蚀的航路
  -> 第五章：第 09 隔离关口
     -> 协助封控：第七章 -> 第九章帝国终局
     -> 冲破封锁：第六章 -> 第九章叛军终局
     -> 深岩救援：第八章 -> 第九章深岩终局
  -> 对应全线结果卡 / 重新部署
```

现阶段每章都已拥有：章节状态、进入对白、短战斗目标、保护对象或互动目标、失败重试、章节结果和下一章跳转。它们是“完整故事线可走通”的骨架，不等同于每章都已达到正式内容量。

## 2. 分批完善顺序

### 批次 A：叙事可读性（下一步，P0）

1. 每章增加章节标题卡、当前证据摘要和“为什么要去下一章”的一句明确因果。
2. 给 Alice、Bob、Charlie 的每个关键事件补齐三人不同的台词与头像，而不是只有玩家变体。
3. 建立“证据档案”面板，持续显示：
   - 航母保护航迹；
   - 货单覆盖；
   - 生命热源；
   - 身份注销；
   - 锈蚀记录；
   - 协处理器位置包；
   - 黑匣广播链。
4. 为第九章结局增加本局证据、救援对象、路线代价和已见人物关系摘要。

**完成定义：** 不看外部 Markdown，玩家也能复述主线的因果、两种风险及自己路线的代价。

### 批次 B：章节差异与核心机制（P0）

1. 将当前通用“守点 / 打节点 / 收核心”原语扩展为专用机制：
   - 第一章：航母掩护碰撞与航迹回放；
   - 第二章：多船护航和扫描层级；
   - 第三章：中继公开度与坐标遮蔽；
   - 第四章：接口干扰、位置包追踪；
   - 第五章：三方同时倒计时；
   - 第六章：民船避让与牵引锁；
   - 第七章：医疗配额/档案节点；
   - 第八章：过滤资源/隔离舱容量；
   - 第九章：广播上传与旧友旗舰非致死解法。
2. 每章设置至少一种失败条件和一种非“清空敌人”的胜利条件。
3. 保证三名驾驶员的主动能力均能与本章目标发生有效互动。

**完成定义：** 章节不只是换标题和敌人数量；每章至少有一项无法用纯 DPS 替代的任务动作。

### 批次 C：人物与关系（P1）

1. 建立三人的关系值不是数值分支，而是“记忆回放/通讯优先级/战斗提示”变化。
2. 为 Bob 的接口增加可见但不替玩家代选的诊断提示。
3. 为 Charlie 增加旧战场撤离记忆与“先撤离再交火”的战术收益。
4. 为 Alice 增加平民信号/救援牵引的高风险回报，而非只增加速度。
5. 让玛拉、军医、矿工、工程师作为具体的人出现，不只充当任务图标。

**完成定义：** 玩家选择任一驾驶员，都能在至少三次关键事件中感到该角色的判断方式改变了信息和打法。

### 批次 D：美术、音频与 UI（P1）

1. 新增第 03–09 章背景、关口、广播塔、深岩、旗舰与锈蚀单位素材。
2. 使用形状、文字和图标共同表达路线，不能仅靠蓝/红/绿颜色。
3. 分开呈现普通通讯、证据档案、紧急选择和最终结果，避免右上 HUD 承载全部文本。
4. 为求救、扫描、接口故障、封门、牵引锁、上传成功分别加入音效/触感占位。
5. 适配窄屏横屏：关口三选卡、结局卡、证据面板必须可读可点。

**完成定义：** 关键信息在静音、色觉差异和小尺寸屏幕下仍可理解。

### 批次 E：数值、回归与正式化（P1）

1. 给每章独立配置敌人血量、弹幕、保护对象生命、波数、上传时长与掉落量。
2. 建立故事/标准难度配置；难度只能改变战斗数值，不得改剧情事实或路线。
3. 自动化流程测试覆盖：序章跳过、三次扫描、三项 Gate 选择、三条第九章终局、失败重试和重新部署。
4. 清理旧版 `branch`、旧分支 Boss、过时图标和不再使用的资源引用。
5. 为 Swift/SpriteKit 正式客户端把 `StoryBranch` 替换为 Gate 09 `RouteID`，并把章节数据移出 HTML。

**完成定义：** 三条线路可重复通关，重试/重新部署不串档，叙事状态可由测试验证。

## 3. 每次迭代的固定规则

- 一次只完善一个章节或一个共用机制，完成后跑完整主线静态契约与对应路线 smoke test。
- 先写/更新 `dialogue-story.md` 和章节验收，再改战斗逻辑；禁止靠临时硬编码台词补剧情。
- 新机制必须说明：玩家动作、失败条件、成功条件、叙事信息、三位驾驶员如何不同。
- 新增剧情前先确认它不会把帝国、余烬或深岩写成纯粹正义/邪恶。
- 每次修改更新 `docs/worklog.md`，并在本文件对应行删除“待补”项或细化验收。

## 4. 当前不应优先做的事项

- 不先扩展局外货币、抽卡、联网、排行榜或收费系统。
- 不把深岩线做成无代价“真结局”。
- 不用增加敌人数量替代章节机制。
- 不在事实基线尚未统一前大规模生成最终美术或配音。
